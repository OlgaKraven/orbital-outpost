1. Прочитать донесение

Рейс E01 уже подготовлен для ремонта антенны. Штаб обновил карточку M01 в каталоге. Задача — написать обработчик запуска и проверить, какое количество будет списано.

В этой первой практике сервер обслуживает один рейс. Данные хранятся в памяти. Перезапуск возвращает начальное состояние. В полном проекте по карте партии и история сохраняются в SQLite.

Открыть анимацию запуска E01

2. Запустить заготовку

Распаковать студенческий комплект. Открыть PowerShell в каталоге first-api. Для запуска нужен .NET SDK 10.

dotnet run --no-launch-profile --urls http://localhost:5201

Открыть состояние рейса в браузере. Найти stock, agreedCost, currentCost, status и history. Записать прогноз остатков. Остановить сервер сочетанием Ctrl+C перед правкой файла.

3. Написать команду запуска

В заготовке уже есть GET и тип LaunchRequest. Добавить перед app.Run() обработчик POST /api/expeditions/E01/transitions. Для сравнения ниже показана команда открытия шлюза. Она проверяет имя команды и текущее состояние до изменения данных.

var hatchOpen = false;
app.MapPost("/example/hatch", (LaunchRequest request) =>
{
    if (request.Action != "open")
        return Results.BadRequest(new { error = "invalid_action" });
    if (hatchOpen)
        return Results.Conflict(new { error = "already_open" });

    hatchOpen = true;
    return Results.Ok(new { hatchOpen });
});
  1. Принять LaunchRequest. Если action отличается от launch, вернуть 400.
  2. Проверить статус prepared. При другом статусе вернуть 409 до изменения состояния.
  3. Выбрать источник стоимости между agreedCost и currentCost. Записать причину выбора в протоколе. Рассчитать остаток каждого ресурса и присвоить stock новый Resources.
  4. Присвоить статус inFlight, добавить его в history, вернуть 200 с полями status и stock.

Проверка сборки. Запустить dotnet run. При ошибке открыть первую строку с именем Program.cs и номером строки. Сверить скобки обработчика и расположение кода перед app.Run().

4. Проверить двумя запросами

В файле requests.http выполнить GET и два одинаковых POST подряд. Между запросами сервер продолжает работать. При отсутствии поддержки .http выполнить блок PowerShell ниже дважды.

$launch = @{
    Uri = 'http://localhost:5201/api/expeditions/E01/transitions'
    Method = 'Post'
    ContentType = 'application/json'
    Body = '{"action":"launch"}'
}
try {
    $reply = Invoke-WebRequest @launch
    $reply.StatusCode
    $reply.Content
} catch {
    if (-not $_.Exception.Response) { throw }
    [int]$_.Exception.Response.StatusCode
}
Invoke-RestMethod http://localhost:5201/api/game | ConvertTo-Json -Depth 6

Для каждого запроса записать HTTP-код, статус рейса, запас и историю. Для автоматической проверки свежего запуска можно выполнить ./Check-E01.ps1 из папки first-api. Затем остановить сервер и запустить с новыми текущими условиями.

dotnet run --no-launch-profile --urls http://localhost:5201 --LaunchTransfer true

Проверить через GET, что каталог стал 8/4. Предсказать результат запуска и его повтора. Сдать папку first-api и протокол обоих наборов.

5. Сверить результат

Открыть эталон E01 после проверки

В вашем проекте first-api маршрут GET /api/game читает состояние для прогноза. POST /api/expeditions/E01/transitions передаёт команду {"action":"launch"} для конкретного рейса.

ПроверкаКод и наблюдениеПочему
Чтение перед запуском200 · prepared, склад 10/5, снимок 6/2, каталог 7/3, история [prepared]Склад показывает физический запас. Снимок хранит условия уже подготовленного рейса. Каталог показывает новые условия M01. При чтении ни одна из записей не меняется.
Первый запуск E01POST: 200, статус inFlight, склад 4/3. Следующий GET: история [prepared, inFlight]Статус prepared допускает запуск. Рейс согласован на 6 топлива и 2 пайка, поэтому остаток равен 10 − 6 = 4 и 5 − 2 = 3. Успешный переход добавляет одно событие.
Повтор той же командыPOST: 409. Следующий GET: inFlight, склад 4/3, прежняя историяРейс уже в полёте. Проверка статуса срабатывает до списания и добавления события. Состояние после отказа проверяют через GET.
Свежая партия с каталогом 8/4Сначала 200, затем 409. После обоих запросов склад 4/3Изменился currentCost. Снимок agreedCost по-прежнему равен 6/2. Первый запуск использует снимок, повтор отклоняется по статусу.
Неизвестная команда, например action: open400 · состояние сохраняетсяОбработчик принимает только launch и проверяет имя команды до работы с состоянием.

6. Перейти к проекту по карте

На станции 6 перенести идею снимка в модель SQLite, на станции 7 — свои проверки в протокол API. В тренажёре открыть «Сценарии» и выбрать «Перенос E01». У рейса будет выданный сервером UUID. В минимальной практике его роль выполняет постоянный код E01.

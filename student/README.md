# Старт проекта «Орбитальный форпост»

Постановка, досье, визуальный тренажёр и пустые листы лежат на уровень выше этой папки. В этой заготовке доступны чтение исходных данных и проверка запуска. Предметные маршруты следует разработать по карте.

## Первый запуск

Открыть PowerShell в папке starter. Требуется .NET SDK 10.

```powershell
dotnet restore
dotnet run --urls http://127.0.0.1:5201
```

В другом окне выполнить:

```powershell
Invoke-RestMethod http://127.0.0.1:5201/healthz
Invoke-RestMethod http://127.0.0.1:5201/study/fixtures | ConvertTo-Json -Depth 8
```

Ожидание: status = ok, в seed видны M01–M03, в scenarios есть учебные наборы и новая редакция M01. Первая практика E01 находится в отдельной папке first-api на уровень выше.

## Реализация

1. Сохранить артефакты ЛР01–ЛР08. Выбрать ветвь А или Б, связать требования с полями и запросами.
2. Создать schema.sql по модели. Открывать соединение SqliteConnection, включить внешние ключи, хранить файл в каталоге state. Для учебного варианта достаточно транзакции записи, охватывающей чтение предусловий, списание или замену и запись события.
3. Добавить группу /api, маршруты каталога и состояния. При создании партии без параметра загрузить исходный seed. При выборе сценария из scenarios.json создать партию с указанным запасом, подготовить исходную M01 и применить редакцию каталога в заданном порядке.
4. Реализовать команды, применяя правила из ЛР05. Номер принятой редакции поступает от клиента. Количество, награда и переходы вычисляются на сервере.
5. Выполнить запросы из requests.http. Вставить реальные ID в начало файла. Каждый блок запроса выполняется отдельно.

Если редактор не выполняет .http, для чтения состояния после реализации создать отдельную партию в PowerShell:

```powershell
$base = 'http://127.0.0.1:5201/api'
$party = Invoke-RestMethod -Method Post -Uri "$base/demo/games?scenario=briefing"
$headers = @{ 'X-Game-Id' = $party.id }
Invoke-RestMethod -Uri "$base/game" -Headers $headers | ConvertTo-Json -Depth 8
Invoke-RestMethod -Uri "$base/expeditions/$($party.activeExpedition.id)" -Headers $headers | ConvertTo-Json -Depth 8
```

## Приёмка

Для самостоятельной проверки нужен Node.js 22+. При запущенном приложении выполнить команду для своей ветви:

```powershell
node check-api.mjs http://127.0.0.1:5201 A
node check-api.mjs http://127.0.0.1:5201 B
```

Ветвь B включает общие проверки и замену. Команда создаёт независимые партии, а ошибки описывает с запросом и ожидаемым результатом. Сохранить снимок состояния до и после одного отказа и повторить чтение сохранённой партии после перезапуска. Протокол и решение приложить к сдаче.
